# FreelanceApp

WPF-приложение для фриланс-платформы: пользователи могут вести профиль и портфолио, публиковать проекты, работать с заказами, оставлять отзывы, искать исполнителей и отправлять жалобы. Для администратора предусмотрена отдельная панель управления пользователями, аудитом и модерацией жалоб.

Проект сделан как курсовое desktop-приложение на .NET/WPF с PostgreSQL в качестве хранилища данных.

## Возможности WPF-приложения

### Авторизация и стартовый сценарий

- стартовое окно с выбором входа или регистрации;
- регистрация нового пользователя с проверкой обязательных полей;
- вход по email и паролю;
- хеширование паролей через SHA-512;
- маршрутизация после входа: администратор попадает в admin-панель, остальные пользователи - в пользовательскую панель.

### Пользовательская панель

Пользовательская часть построена вокруг вкладок:

- **Профиль** - редактирование ФИО, email, телефона, пола, пароля и фотографии; просмотр приглашений и предупреждений.
- **Портфолио** - добавление, редактирование и удаление записей портфолио, навыков, опыта и медиа.
- **Заказы** - просмотр заказов в ролях заказчика и исполнителя, работа с архивом, изменение статуса и дедлайна.
- **Проекты** - создание, редактирование, удаление и фильтрация проектов; отклики на открытые проекты.
- **Отзывы** - добавление, изменение и удаление отзывов по завершенным заказам, оценка по шкале 1-5, поддержка изображения.
- **Жалобы** - создание жалобы по заказу, просмотр своих жалоб, редактирование описания и вложений.
- **Поиск исполнителей** - поиск фрилансеров по имени и навыкам, выбор проекта и отправка приглашения.

### Административная панель

Для пользователей с ролью `admin` доступна отдельная панель:

- управление пользователями: создание, редактирование, удаление, назначение ролей;
- просмотр карточек пользователей с контактами, рейтингом, датой регистрации и временем последней активности;
- просмотр audit log с фильтрацией по датам;
- импорт и экспорт журнала аудита в JSON;
- модерация жалоб: фильтрация, поиск, смена статуса, взятие в работу, отклонение, закрытие и выдача предупреждений.

### Интерфейс

- WPF/XAML UI с отдельными окнами и пользовательскими контролами;
- MVVM-подход на базе `CommunityToolkit.Mvvm`;
- светлая и темная темы через словари ресурсов;
- локализация RU/EN через XAML resource dictionaries;
- единые стили для окон авторизации, панелей, карточек, вкладок и форм.

## Запуск приложения

### Требования

- Windows;
- .NET 9 SDK;
- Visual Studio 2022, JetBrains Rider или другой IDE с поддержкой WPF;
- PostgreSQL;
- подготовленная база данных и строки подключения в `FreelanceApp/appsettings.json`.

### Сборка из консоли

```powershell
dotnet restore app.sln
dotnet build app.sln
dotnet run --project FreelanceApp/FreelanceApp.csproj
```

Также можно открыть `app.sln` в Visual Studio и запустить проект `FreelanceApp`.

## Конфигурация подключения

Строки подключения находятся в `FreelanceApp/appsettings.json`:

```json
{
  "ConnectionStrings": {
    "svc_app": "Host=localhost;Database=oop_course_db;Username=svc_app;Password=...",
    "app_end_usr": "Host=localhost;Database=oop_course_db;Username=app_end_usr;Password=...",
    "svc_admin": "Host=localhost;Database=oop_course_db;Username=svc_admin;Password=..."
  }
}
```

Перед публикацией или переносом проекта замените локальные пароли и проверьте, что имя базы данных совпадает в SQL-скриптах и в `appsettings.json`.

## База данных

PostgreSQL используется как основное хранилище. Приложение работает со схемой `core` через EF Core, представления, функции и хранимые процедуры.

Основные сущности:

- `roles`, `users` - роли и пользователи;
- `portfolio` - портфолио и навыки;
- `projects` - проекты заказчиков;
- `orders`, `orders_archive` - активные и архивные заказы;
- `reviews` - отзывы и рейтинги;
- `complaints` - жалобы;
- `warnings` - предупреждения пользователям;
- `notifications` - приглашения и системные уведомления;
- `audit_logs` - журнал изменений.

SQL-часть вынесена в `Note/database scripts/`:

- `new_tables.sql` - таблицы и ограничения;
- `new_views.sql` - представления;
- `new_procedures.sql` - функции и процедуры бизнес-логики;
- `new_audit.sql` - аудит и триггеры;
- `new_roles.sql` - роли PostgreSQL, база данных и права доступа;
- `users_data.txt` - заметки по сервисным пользователям.

Типовой порядок подготовки БД:

1. Создать роли и базу `oop_course_db` по `new_roles.sql`.
2. Подключиться к созданной базе.
3. Выполнить скрипты таблиц, представлений, процедур и аудита.
4. Проверить гранты для `svc_app`, `app_end_usr` и `svc_admin`.
5. Синхронизировать строки подключения в `FreelanceApp/appsettings.json`.

ER-диаграмма доступна в [Note/diagrams/er/oop_db.svg](https://github.com/zmorok/course_oop/blob/master/Note/diagrams/er/oop_db.svg).

## Архитектурные заметки

- `FreelanceApp` отвечает за UI, навигацию, команды, локализацию и темы.
- `DAL` инкапсулирует `FreelanceAppContext`, модели таблиц/представлений и репозитории.
- Репозитории разделены на пользовательские и административные сценарии.
- `UnitOfWork` объединяет репозитории и транзакционные операции.
- Основная бизнес-логика работы с данными находится в PostgreSQL-процедурах схемы `core`.

## Статус проекта

Проект ориентирован на учебный сценарий и локальный запуск. Для production-использования нужно вынести секреты из `appsettings.json`, привести SQL-инициализацию к миграциям или единому bootstrap-скрипту и добавить автоматизированные тесты.
